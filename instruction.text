# Project Update: Job Search, CV Match Scoring, Cover Letter Chat, and PhD Discovery

## Objective

Update my existing AI-powered job search application. Do not rebuild the project from scratch. Inspect the current implementation and reuse the existing React, TypeScript, Vite, Express.js, MongoDB, Docker, and OpenRouter integrations.

The application must have two main sections:

1. **Professional Jobs**
2. **PhD Opportunities**

Both sections must support CV-based matching and tailored cover letter generation. The job section must enforce a three-month posting-age limit, while the PhD section must include every suitable position whose application deadline has not passed.

## 1. Professional Jobs Section

### Target job categories

Search for jobs matching my CVs in these categories:

- Full Stack Developer / Engineer
- Senior Full Stack Developer
- AI Developer / AI Engineer
- LLM Engineer / Generative AI Engineer
- Software Engineer working with AI
- DevOps Engineer
- Cloud Engineer
- Platform Engineer
- Related roles when my actual skills and experience are a good fit

Allow me to configure additional job titles and keywords in settings.

### Geographic filtering

**Jobs within Germany:**
- Remote
- Hybrid
- Onsite / office-based, including daily office attendance

Search across Germany, not only near my current location.

**Jobs outside Germany:**
- Remote positions only
- The employer must explicitly permit remote work from Germany or the listing must provide reliable evidence of eligibility
- Exclude onsite and hybrid positions outside Germany

Do not assume that a job marked “remote” can be performed from any country.

### Language requirements

Only show jobs where English is sufficient for the role.

Include positions where German is optional, preferred, advantageous, or a plus.

Exclude positions where German is mandatory. If the language requirements are unclear, mark the listing for review instead of assuming it is eligible.

## 2. Professional Job Posting Date Rules

**Only display professional jobs posted within the last three calendar months.**

Use the original posting date from the job source whenever available.

For example, if the current date is October 26, 2026, a job posted before July 26, 2026, should not appear in the normal job results. Use consistent calendar-month arithmetic and the appropriate date boundary.

Implement the following behavior:

- Jobs posted within the permitted period: display normally.
- Jobs posted more than three calendar months ago: exclude from the results.
- Jobs with unknown or unverifiable posting dates: exclude from the normal results and optionally show them in a separate review view.
- Jobs that are expired or no longer accepting applications: exclude.
- Jobs reposted recently: use reliable evidence of the new posting date and do not automatically assume the listing is new.

Add date filters:
- Last 24 hours
- Last 7 days
- Last 14 days
- Last 30 days
- Last 3 months
- Custom date range

These filters must operate within the overall three-month limit. Selecting a broader date range must never reveal older jobs.

Apply the date eligibility check in the backend, not only in the frontend.

## 3. CV-Based Job Match Percentage

Read and parse all three of my existing CVs.

Use them to calculate an explainable match percentage for each professional job.

Consider:
- Required technical skills
- Preferred technical skills
- Relevant work experience
- Responsibilities
- Seniority
- Programming languages and frameworks
- AI, LLM, and RAG experience
- Cloud and DevOps experience
- Education and qualifications

Use a consistent, documented scoring method. Do not simply ask the LLM to invent a percentage.

For each job, display:
- Overall match percentage from 0% to 100%
- Best matching CV
- Matching skills
- Missing required skills
- Relevant experience
- Potential concerns
- Explanation of the score

The percentage is an estimated profile match, not a probability of getting an interview or receiving an offer.

Location, language, and employment eligibility must be applied as mandatory filters rather than compensated for by a high match score.

Add filters for match score, job category, location, working arrangement, company, and posting date.

## 4. Professional Job Details and Cover Letter Chat

When I click a job, open a detailed view containing the original job description, company, location, posting date, required skills, match percentage, and match explanation.

Provide a dedicated AI chat for that job.

I should be able to ask questions such as:
- Why am I a good match for this role?
- Which of my skills should I emphasize?
- Which CV is best for this position?
- What experience is missing?
- Can you write a cover letter for this job?
- Can you improve the introduction?
- Can you rewrite this paragraph?
- What should I highlight to address the job requirements?

The chat must use the current job description, my CVs, existing cover letters, match analysis, and relevant conversation history.

Keep each job's conversation separate from every other job.

### Cover letter creation

Provide both of these options:

1. **Generate Cover Letter** button
2. **Write or refine my cover letter through chat**

When generating a cover letter, use:
- The complete available job description
- All three CVs as information sources
- All three existing cover letters as writing references
- The most relevant CV and reference letter for the role

Generate a professional, tailored English-language letter that reflects my real experience and the job's requirements.

Allow me to:
- Edit the generated letter
- Ask the chat to revise it
- Regenerate it
- Copy it
- Download it
- Save different versions

Never invent achievements, qualifications, skills, or employment history.

Save the generated and edited versions in MongoDB. Generating a letter must never submit a job application.

## 6. PhD Deadline Rules

**For PhD positions, the application deadline is the main date eligibility condition.**

Do not apply the three-month posting-age restriction to PhD positions.

Include relevant PhD positions regardless of when they were originally posted, provided that:
- The application deadline has not passed.
- The position is still open and accepting applications.
- The position matches my research interests and qualifications sufficiently to be relevant.

For example, a PhD position posted six months ago should still be displayed if its verified deadline is in the future and the opportunity remains open.

Implement these rules:

- Deadline in the future: eligible to display if the position remains open.
- Deadline today: display if applications are still being accepted, taking the institution's local timezone and deadline time into account when available.
- Deadline passed: exclude from active opportunities.
- Deadline unknown: place in a separate “Deadline Needs Verification” group instead of assuming it is still open.
- Position explicitly closed or filled: exclude even if the displayed deadline is in the future.
- Rolling admissions: include when the official source confirms applications are still accepted.

Store:
- Original posting date, if available
- Application deadline
- Deadline timezone, when available
- Date last verified
- Current status
- Official source URL

Recheck the official source before treating an opportunity as open. Clearly flag deadlines that cannot be verified.
